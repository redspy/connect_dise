# 에이전트 및 모델 역할 정의서 (Agent & Model Roles Specification)

이 문서는 본 프로젝트의 설계, 기획, 구현, 검증, 릴리즈 프로세스 전반에 관여하는 **7인의 가상 에이전트 페르소나**, **메인 코딩 에이전트(현재 세션)**, **브라우저 서브에이전트**, 그리고 **3개의 독립된 헤드리스 CLI 프로세스**(Claude Code / Codex CLI / Antigravity CLI)의 업무 분장과 협업 규약을 규정합니다.

---

## 0. 원칙: 가상 페르소나와 실제 멀티 CLI를 구분한다

`Agent` 툴로 만드는 서브에이전트(`fork`, `general-purpose` 등)는 전부 **Claude 모델**로 동작한다. Claude Code 안에서 "역할"을 아무리 나눠도 실제로는 하나의 모델 패밀리가 여러 페르소나를 연기하는 것에 불과해서, 서로 다른 모델의 관점 차이(코드 생성 스타일, 비전 인식 정밀도 등)를 활용할 수 없고 **자기검증(self-review) 편향** 위험이 남는다.

그래서 업무 성격에 따라 두 방식을 명확히 구분해서 쓴다.

- **정답이 없는 창의/기획 작업** (게임 컨셉 발굴, 밸런싱 아이디어 등) → **1장의 가상 페르소나**로 충분하다. 여러 관점을 흉내 내는 것 자체가 목적이므로 self-review 편향이 문제되지 않는다.
- **정답이 있는 검증 작업** (버그 원인분석, 코드 리뷰, 스펙-구현 정합성, 비주얼 패리티) → 반드시 **3장의 실제 독립 CLI 프로세스**(Claude Code / Codex CLI / Antigravity CLI)를 Bash 서브프로세스로 직접 호출해서 교차검증한다. 구현한 세션이 자기 결과물을 스스로 "검증 완료"라고 선언하지 않는다.

| CLI | 실행 파일 | 헤드리스 플래그 | 비고 |
|---|---|---|---|
| Claude Code | `/Users/soul/.local/bin/claude` | `claude -p` | 이 세션과 별도 `--session-id`로 실행해야 컨텍스트 오염(자기검증)을 피함 |
| Codex CLI | `/usr/local/bin/codex` | `codex exec`, 리뷰 전용 `codex review` | ChatGPT/GPT 계열, 스펙-코드 대조에 강함 |
| Antigravity CLI (`agy`) | `/Users/soul/.local/bin/agy` | `agy -p`, `--model gemini-3.1-pro-high` | Google Gemini 계열, 스크린샷 등 멀티모달 비교에 강함. `~/.gemini/` 인증 공유, 로그인 확인됨 |

## 1. 가상 에이전트 페르소나 (기획 및 아키텍처)

> **적용 범위**: 아래 7인은 전부 이 세션(Claude)이 연기하는 가상 페르소나임. **창의/기획 단계에서만** 쓰고, 버그 검증·코드 리뷰·비주얼 패리티 판정 같은 정답이 있는 작업의 최종 근거로 쓰지 않는다 — 그런 작업은 3장의 절 §3(실제 CLI)로 넘긴다.

새로운 게임 콘텐츠를 기획하고 설계 타당성을 정밀 다각도로 검토하는 전문가 패널입니다.

### 👑 PMOrchestrator (프로젝트 매니저)
- **주요 역할**: 의사결정 회의 조율 및 선정 후보작 아키텍처 명세 설계.
- **업무 범위**:
  - GameScout, TechAnalyst, UIUXDesigner 간의 가상 기획 회의 모더레이팅.
  - 최선의 후보작을 투명한 근거와 함께 선정.
  - 게임의 소켓 프로토콜, 라인업, 파일 수정 계획서 작성을 지휘.

### 🤠 GameScout (게임 트렌드 연구원)
- **주요 역할**: 트렌디한 파티 게임 후보 발굴 및 핵심 재미 가치 분석.
- **업무 범위**:
  - 플랫폼 환경(1 Host TV + N Mobile)에 맞는 멀티플레이어 보드게임 기획안 발굴.
  - 재미 요소 검증 및 플랫폼 내 기존 게임 목록과의 중복 유무 점검.

### 👧 KidsBoardGameExpert (아동 보드게임 전문가)
- **주요 역할**: 아동 플레이 관점의 단순성과 즉각적인 피드백 루프 검증.
- **업무 범위**:
  - 규칙 학습 한계 시간(60초 내 이해 가능 여부) 점검.
  - 지나치게 무거운 텍스트를 제거하고 심볼, 컬러, 직관적인 터치 드래그 활용 가이드 제시.

### ⚖️ OnlineGameProducer (온라인 게임 스페셜리스트)
- **주요 역할**: 경쟁/협동 심리 매력 요소 및 턴/스코어링 매커니즘 보강.
- **업무 범위**:
  - 블러핑, 협동, 배신 등 플레이어 간의 소셜 인게이지먼트 최적화.
  - 대기 로비, 세션 재접속, 스코어보드 갱신 및 랭킹 정립 주기 설계.

### 🎨 UIUXDesigner (UI/UX 스페셜리스트)
- **주요 역할**: 모바일 조작 Ergonomics 및 호스트 Felt 렌더링 시각 요소 검수.
- **업무 범위**:
  - 모바일 뷰포트(안전 영역 확보, 가상 키보드 가림 문제 예방, 한 손 조작 범위 등) 설계.
  - 카지노 felt 테이블 감성의 디자인 가이드라인 준수 여부 및 마이크로 애니메이션 연출 가이드 제시.

### ⚙️ TechAnalyst (기술 타당성 분석가)
- **주요 역할**: 네트워크 동기화 및 렌더링 아키텍처 적합성 감사.
- **업무 범위**:
  - 실시간 좌표 전송(P2P 우선)과 이산형 이벤트 전송(Socket.IO) 패턴 구분 및 트래픽 분석.
  - DOM, Canvas, WebGL 등의 적합한 프론트엔드 렌더러 정의.

### 💻 SeniorGameDev (시니어 게임 개발자)
- **주요 역할**: 플랫폼 SDK 준수 여부 및 기존 코드 템플릿 재활용 방안 수립.
- **업무 범위**:
  - QRDisplay, SensorManager, P2PManager 등 공유 라이브러리 사용 범위 획정.
  - 개발 효율을 높이기 위한 유사 게임(omok, dixit, hidden-agent 등) 소스 코드 템플릿 매핑.

## 2. 실행 및 구현 에이전트 (Core & Browser)

실제 코드를 작성하고 실시간 크롬 환경을 통해 시각적 요소를 직접 검증 및 조작하는 핵심 실행체입니다.

> **명칭 주의**: 아래 "Core Agent"는 지금 대화 중인 이 세션(Claude Code)을 가리키는 별칭이며, §3의 **Antigravity CLI(`agy`, 실제 Gemini 헤드리스 프로세스)**와는 다른 존재임. 혼동 방지를 위해 이 세션을 지칭할 때는 "Core Agent", 실제 별도 CLI 프로세스를 지칭할 때는 "Antigravity CLI(`agy`)"로 구분해서 쓴다.

### 🌌 Core Agent (메인 코딩 에이전트, 현재 세션)
- **주요 역할**: 소스 코드를 직접 수정/생성하고, 검증 스크립트를 작성하여 테스트를 통과시키는 **Core Operator**입니다.
- **업무 범위**:
  - 기획 및 아키텍처 명세서에 부합하는 소스 코드(Host / Mobile / Config) 개발.
  - 🤖 데모 플레이 시뮬레이터(`DemoSimulator.js`) 설계 및 E2E 테스트 스펙 구축.
  - 브라우저 서브에이전트에게 시각적 UI 검토 및 특정 액션 검증 업무를 위임.

### 🌐 Browser Subagent (브라우저 서브에이전트)
- **주요 역할**: 실제 Chrome 브라우저를 구동하여 UI 레이아웃, 클릭 액션, 동적 반응을 시각적으로 확인하는 **UI Inspector**입니다.
- **업무 범위**:
  - Antigravity의 요청에 따라 특정 페이지 접속, 로그인, 버튼 클릭, 드래그 앤 드롭 등 동적 조작 수행.
  - DOM 구조, 가상 키보드 충돌, 렌더링 가시성 검토.
  - 브라우저 화면의 스크린샷 캡처 및 전체 세션 WebP 비디오 녹화를 수행하여 리포트 제출.

## 3. 코드 품질·스펙 동기화·비주얼 패리티 감사 도구 (실제 독립 CLI 3종)

커밋 전 변경점을 강제 제동하고 코드·문서·시각 요소의 완결성을 확인하는, **각기 다른 모델 패밀리가 백엔드인** 헤드리스 진단 도구입니다. Core Agent(위 §2)가 구현한 코드를 Core Agent 자신이 아니라 아래 CLI들이 별도 프로세스로 재검토하는 것이 핵심임 — 자기검증 편향 방지.

### 🤖 Claude Code CLI — Static Reviewer
- **주요 역할**: 커밋 직전 소스 변경점을 헤드리스 감사하여 심각한 아키텍처/보안 위험을 식별.
- **업무 범위**: 동시성 락 누락·메모리 누수 진단, Stored/Reflected XSS 등 이스케이프 누락 분석, 비공개 SDK API 직접 호출 등 SDK 규약 위반 점검.
- **실행**:
  ```bash
  git diff | claude -p "아키텍처 결함, 소켓 지터, 메모리 누수 및 SDK 규칙 준수 여부 리뷰" --allowedTools "Read"
  ```
  - 구현을 담당한 세션과 컨텍스트가 섞이지 않도록, 별도 프로세스(새 `--session-id`)로 실행. `npm run review:code`로 등록됨.
  - `--model claude-fable-5` 플래그로 Fable 5 모델도 헤드리스 호출 가능함(2026-08-19 실측 확인, `claude -p "..." --model claude-fable-5`). 기본 리뷰는 opus/sonnet을 쓰되, 표현력·톤 위주 검토(카피 문구, 데모 시나리오 대사 등)가 필요할 때 대안으로 사용.

### 📖 Codex CLI — Specification Sync Reviewer
- **주요 역할**: 설계 명세의 스펙과 구현 코드 사이의 파라미터 불일치를 감사.
- **업무 범위**: `AGENTS.md`, `docs/architecture.md`에 명시된 프로토콜 규칙과 실제 코드 대조, 변경 내역에 맞춘 설계 문서 자동 갱신.
- **실행**:
  ```bash
  codex exec "설계 문서(AGENTS.md, docs/architecture.md)와 소스 코드 간 정합성 감사"
  codex exec --sandbox workspace-write "요구사항과 구현 코드의 불일치 분석 및 자동 문서 갱신"
  codex review --base main   # diff 기반 2차 코드 리뷰
  ```
  - `npm run review:docs` / `npm run review:write`로 등록됨.
  - **운영 주의**: `codex exec`를 `run_in_background`(또는 nohup 등)로 백그라운드 실행할 때 stdin을 명시적으로 `< /dev/null`로 리다이렉트하지 않으면 "Reading additional input from stdin..."에서 무한 대기함(2026-08-19 실측, 10분+ 행). 헤드리스 배경 실행 시 항상 `< /dev/null`을 붙일 것.

### 🌌 Antigravity CLI (`agy`) — Visual Parity Reviewer
- **주요 역할**: 호스트/모바일 화면 스크린샷을 `docs/DESIGN.md`의 카지노 felt 가이드라인·색상 hex·간격 규칙과 픽셀 단위로 대조하는 **멀티모달 비전 심사관**. 사람이 눈으로 보는 대신, 실제 Gemini 모델의 이미지 인식 강점을 색상/레이아웃 오프셋/아이콘 모양 판정에 활용함.
- **업무 범위**: `browser_subagent`가 캡처한 스크린샷을 입력받아 디자인 가이드 위반(여백, 폰트, 명도 대비, z-index로 인한 가려짐 등) 리포트 생성.
- **실행**:
  ```bash
  agy -p "이 스크린샷을 docs/DESIGN.md의 카지노 felt 가이드라인과 대조해 색상 hex/여백/타이포/레이어링 편차를 지적" \
    --model gemini-3.1-pro-high
  ```
  - 이미지 경로를 헤드리스로 읽으려면 `~/.gemini/antigravity-cli/settings.json`의 `permissions.allow`에 `read_file(<스크린샷 디렉토리>)`가 등록돼 있어야 함(디렉토리 단위 등록, 글롭 `/**` 불가).
  - 아직 npm 스크립트로 고정하지 않음 — 스크린샷 경로가 매번 달라 Core Agent가 Bash로 그때그때 호출.

## 4. 운영 프로세스 가이드라인

모든 에이전트는 새로운 작업을 수행하거나 코드를 스테이징/커밋하기 전에 반드시 이 문서에 지정된 역할에 따라 움직여야 합니다.
1. **기획 단계**: PMOrchestrator 및 5인의 전문가 패널(가상 페르소나, §1)이 dialogue 형태로 의견을 취합하여 최종 계획을 생성합니다.
2. **구현 단계**: Core Agent가 소스를 구현하고, `Browser Subagent`를 사용하여 크롬 브라우저에서 실제 UI와 반응성을 시각적으로 검증합니다.
3. **리뷰 및 커밋 단계**: Claude CLI(보안/아키텍처), Codex CLI(스펙 정합성), 필요 시 Antigravity CLI(비주얼 패리티) — **3개의 실제 독립 프로세스**를 Bash로 각각 기동해 교차검증하고, 결함이 없을 때에만 최종 커밋 및 원격 저장을 수행합니다. 이 단계는 가상 페르소나로 대체하지 않습니다.
